# 멋쟁이사자처럼 경상국립대학교 해커톤 2팀(풍차돌리기)

## 서비스 개요
용어집과 상대 정보를 기억하는 AI 번역 도구 - Glossy

### 문제 정의
해외팀, 다른 조직과 영어로 협업할 때의 문제 두가지
1. 사내 약어와 프로젝트 등이 이상하게 번역됨 - 번역기가 고유명사도 번역함.
2. 같은 용어를 팀원마다 다르게 번역함 - 각자 번역기를 돌리니 같은 대상이 문서마다 다른 이름으로 남고, 나중에 합칠 때 동일한 것을 의미하는지 확인하기가 어려움.

### 대표 기능
1. 번역 - 텍스트 입력 -> 용어집과 상대 프로필을 반영해 출력
2. 용어집 - 용어별로 "번역할지 / 용어 그대로 둘지" 지정
3. 용어 자동 추천 -> 승인 - 문서를 넣거나 번역을 쓰다 보면 AI가 등록할 만헌 용어를 제안하고, 사용자가 승인해야 등록됨.
4. 상대 프로필 메모리 - 대화 내용에 상대의 회사/직책을 뽑아 저장(승인 방식)하고, 다음 번역부터 반영.

## Git 가이드
프론트엔드는 `frontend`, 백엔드는 `backend` 브랜치에서 작업 후 PR합니다.
`main` 브랜치에서 직접 작업하거나 merge 하지 말아주세요.
작업 흐름은 아래와 같습니다.
```
main 최신화
→ 작업 브랜치로 이동 or 새 작업 브랜치 생성
→ 파일 수정
→ commit
→ 작업 브랜치 push
→ Pull Request 생성
→ 관리자 리뷰 후 merge
```

### 1. 저장소 클론
작업할 폴더에서 아래 명령어를 실행해 원격 저장소를 로컬로 가져옵니다.
```zsh
git clone https://github.com/Potato-Love/Glossy
```
### 2. main 최신화
작업 전, 아래 명령어를 터미널에 입력해`main` 브랜치의 상태를 최신 상태로 맞춰주세요.
``` zsh
git checkout main
git pull origin main
```
### 3. 작업 브랜치로 이동하기
frontend 관련 작업은 `frontend`브랜치에서, backend 관련 작업은 `backend` 브랜치에서 작업합니다. 
__*`main`브랜치에서 작업하지 않습니다.*__

아래 명령어를 입력해 작업할 브랜치로 변경합니다.
``` zsh
git switch (작업할 브랜치명)
```
작업 중인 브랜치를 확인합니다.
``` zsh
git branch
```
필요 시 새 브랜치를 생성할 수 있습니다.
``` zsh
git switch -c (새 브랜치명)
```
새 브랜치를 생성했다면 아래 구조와 같이 각 파트 하위에 기능 브랜치를 구성해주세요.
```
[브랜치명 규칙]
- `feat/...` : 기능 개발
- `fix/...` : 버그 수정
- `docs/...` : 문서 수정

[예시]
main
├─ frontend
│  ├─ feat/translate
│  ├─ feat/glossary
│  └─ feat/profile
│
└─ backend
   ├─ feat/translate-api
   └─ feat/auth
```
### 4. PR 만들기
commit, push를 완료했다면 Github 저장소에서 `Compare & pull request`버튼을 확인할 수 있습니다.
PR을 만들 때 방향은 아래와 같이 설정해주세요.
``` 
base: main
compare: 작업 브랜치
```
제목에는 변경 내용을 명확하게 작성하고 본문에는 어떤 작업을 했는지 간단히 적어주세요.

코드 리뷰 뒤 관리자가 merge를 진행합니다.
